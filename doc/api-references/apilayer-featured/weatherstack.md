## Authentication
The official quickstart guide states that requests are authenticated with a personal `API Access Key`, passed in examples as the `access_key` query parameter.

## Manually confirmed endpoints
| Method | Path | Purpose | Key documented parameters |
|---|---|---|---|
| GET | `/current` | Real-time weather for specified locations | required `access_key`, required `query`; optional `units`, `language`, `callback` |
| GET | `/historical` | Historical weather for one date or date range | required `access_key`, required `query`; uses `historical_date` or `historical_date_start` + `historical_date_end`; optional `hourly`, `interval`, `units`, `language`, `callback` |
| GET | `/forecast` | Multi-day weather forecast | required `access_key`, required `query`; optional `forecast_days`, `hourly`, `interval`, `units`, `language`, `callback` |
| GET | `/marine` | Marine weather data by coordinates | listed in the official endpoint summary |
| GET | `/locations` | Location autocomplete / lookup | listed in the official endpoint summary |

## Response and usage notes
- The official APILayer docs describe Weatherstack as a RESTful JSON service delivering global real-time, historical, and forecast weather data, plus location autocomplete and marine support.
- The docs state that each location/date pair in a bulk request consumes one API call.
- Documented `units` values are `m`, `s`, and `f`.
- `language` localizes description arrays.
- `format=1` is documented as a pretty-print/debug flag.

## Rate limits, pagination, and errors

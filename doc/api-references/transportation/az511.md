- Category: `Transportation`
- Provider slug: `az511`
- Official docs used manually:
  - `https://www.az511.com/developers/doc`

  - `https://www.az511.com/help/endpoint/weatherstations`
  - `https://www.az511.com/help/endpoint/messagesigns`
  - `https://www.az511.com/help/endpoint/event`
  - `https://www.az511.com/help/endpoint/alerts`
  - `https://www.az511.com/help/endpoint/restareas`
  - `https://github.com/usdot-jpo-ode/wzdx`
- Base URLs:
  - `https://az511.com/api/v2/get`
  - `https://az511.com/api`
- Authentication:
  - V2 traffic endpoints require a developer key in the `key` query parameter.
  - The official developer landing page says most calls require `key`; the public `GET /api/wzdx` feed responded without a key during manual verification.
- Primary response formats:
  - V2 endpoints support `json` or `xml` via the optional `format` query parameter; default is `json`.
  - `GET /api/wzdx` returns JSON (`application/json; charset=utf-8`).
- Transport scope: Arizona traveler-information data for cameras, weather stations, message boards, traffic events, alert notices, rest areas, and a WZDx work-zone feed.

## Important official usage notes
- The official developer page says the REST API covers Cameras, Message Boards, Events, Alerts, Weather Stations, and Rest Areas.
- The official rate limit note is: `Ten calls every 60 seconds`.
- The developer page says a registered AZ511 account is required before requesting a developer API key.
- V2 examples consistently use Unix timestamps for time fields such as `LastUpdated`, `Reported`, `StartDate`, `PlannedEndDate`, `StartTime`, and `EndTime`.
- The WZDx section links to the USDOT WZDx specification and publishes the AZ511 feed at `https://az511.com/api/wzdx`.
- Manual live verification showed the WZDx feed advertising `feed_info.version` `4.1` and returning a GeoJSON-like `FeatureCollection` payload.

## Rate limits, pagination, and errors
- Official rate limit: `10 calls every 60 seconds`.
- No pagination parameters are documented on the inspected AZ511 endpoints; the documented routes return full collections.
- Manual live verification of `GET /api/v2/get/cameras` without a valid `key` returned HTTP `400` with XML body `<Error><Message>Invalid Key</Message></Error>`.
- Manual live verification of `GET /api/v2/get/cameras?format=json` still returned the same XML auth error, so auth failures are not guaranteed to honor the requested output format.
- No broader structured error catalog was documented on the inspected official pages.

## Confirmed API surface
The official AZ511 docs currently expose 7 GET routes:
1. `GET /api/v2/get/cameras`
2. `GET /api/v2/get/weatherstations`
3. `GET /api/v2/get/messagesigns`
4. `GET /api/v2/get/event`
5. `GET /api/v2/get/alerts`
6. `GET /api/v2/get/restareas`
7. `GET /api/wzdx`

## Common request and response notes
- Shared V2 query parameters:
  - `key` - required developer key.
  - `format` - optional output format; valid values are `xml` or `json`; default `json`.
- V2 endpoints are collection-style GET routes with no documented path parameters.
- Response examples show numeric coordinates as doubles.
- The `messagesigns`, `alerts`, and `event` endpoints can include nested arrays/objects and long embedded text or HTML fragments.
- The WZDx feed returns GeoJSON-style `features` plus `feed_info` metadata and follows the linked USDOT WZDx specification rather than the V2 XML/JSON toggle pattern.

## 1) Get cameras
- Method: `GET`
- Path: `/api/v2/get/cameras`
- Full URL: `https://az511.com/api/v2/get/cameras`
- Purpose: return all traffic cameras published by AZ511.

Documented query parameters:
- `key` - required string developer key.
- `format` - optional string; `xml` or `json`; default `json`.

Documented response fields:
- `Id` - integer unique identifier.
- `Source` - source name.
- `SourceId` - source camera identifier.
- `Roadway` - roadway name.
- `Direction` - facing direction such as northbound/eastbound/etc.
- `Latitude`, `Longitude` - coordinates.
- `Location` - camera location label.
- `SortOrder` - integer sort value.
- `Views` - array/object of camera views with `Id`, `Url`, `Status`, `Description`.

## 4) Get events
- Method: `GET`
- Path: `/api/v2/get/event`
- Full URL: `https://az511.com/api/v2/get/event`
- Purpose: return all traffic events.

Documented query parameters:
- `key` - required string developer key.
- `format` - optional string; `xml` or `json`; default `json`.

Documented response fields:
- `ID` - integer unique identifier.
- `SourceId`, `Organization` - source metadata.
- `RoadwayName`, `DirectionOfTravel`, `Description` - event descriptors.
- `Reported`, `LastUpdated`, `StartDate`, `PlannedEndDate` - Unix timestamps.
- `LanesAffected`, `LaneCount` - lane impact details.
- `Latitude`, `Longitude`, `LatitudeSecondary`, `LongitudeSecondary` - geometry points.
- `EventType` - one of `roadwork`, `closures`, or `accidentsAndIncidents` per the docs.
- `EventSubType`, `IsFullClosure`, `Severity` - event-detail fields.
- `EncodedPolyline` - encoded geometry string.
- `Restrictions` - width/height/length/weight/speed restriction object.
- `DetourPolyline`, `DetourInstructions`, `Recurrence`, `RecurrenceSchedules`, `Details` - additional event metadata.

## 7) Get WZDx work-zone feed
- Method: `GET`
- Path: `/api/wzdx`
- Full URL: `https://az511.com/api/wzdx`
- Purpose: return AZDOT's WZDx work-zone feed.

Documented request notes:
- No AZ511-specific query parameters were documented on the developer landing page for this feed.
- The official page links the feed to the USDOT WZDx specification repository.
- Manual live verification succeeded without an API key and returned JSON.

Observed response notes from the live official feed:
- Top-level keys include `feed_info`, `type`, and `features`.
- `feed_info` included `publisher`, `version`, `update_date`, and `data_sources` during manual verification.
- Features use GeoJSON-style `geometry` plus nested `properties`, including `core_details`, `road_event_id`, dates, location fields, and vehicle-impact metadata.

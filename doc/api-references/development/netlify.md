## Authentication
From Netlify's official getting-started page:
- Netlify uses OAuth2 for authentication.
- Personal access tokens (PATs) can be generated from `Applications > Personal access tokens` in account settings.
- API requests authenticate with the Authorization header using the Bearer scheme.
- Public integrations are expected to use OAuth2 with an application client key and client secret.
- The reviewed page explicitly identifies the end-user authorization endpoint as `https://app.netlify.com/authorize`.
- Password resets invalidate previously created personal access tokens and OAuth tokens.
- Teams protected by SAML SSO require explicit token authorization for team access.

## Common request/response conventions
- All URLs start with `https://api.netlify.com/api/v1/`.
- SSL/HTTPS is required.
- The official cURL example includes both a User-Agent header and an Authorization Bearer header.
- The API is versioned in the path; the docs say backward-incompatible changes would use a bumped version marker.

## Manually confirmed endpoint set

### 1) List sites
- Method: `GET`
- Path: `/api/v1/sites`
- Full URL: `https://api.netlify.com/api/v1/sites`
- Purpose: list sites the caller has access to.
- Pagination behavior from the reviewed page:
  - paginated over 100 items by default
  - `page` selects the page number
  - `per_page` customizes page size up to 100
  - pagination links are returned in the HTTP `Link` header

### 2) Create site
- Method: `POST`
- Path: `/api/v1/sites`
- Full URL: `https://api.netlify.com/api/v1/sites`
- Purpose: create a new site.
- The reviewed guide presents this as the first step when creating and deploying a brand new site.
- Response usage note:
  - the returned site identifier is then used to create deploys.

### 3) Get site
- Method: `GET`
- Path: `/api/v1/sites/{site_id}`
- Full URL: `https://api.netlify.com/api/v1/sites/{site_id}`
- Purpose: fetch an individual site's details.
- Path parameter:
  - `site_id` - Netlify site identifier
- The autogenerated route inventory also showed examples of site lookup by concrete ID and site name/domain; in this pass I manually confirmed the canonical `{site_id}` route family from the official getting-started documentation.

### 4) Create deploy
- Method: `POST`
- Path: `/api/v1/sites/{site_id}/deploys`
- Full URL: `https://api.netlify.com/api/v1/sites/{site_id}/deploys`
- Purpose: create a deploy for an existing site.
- Confirmed request-body structure from the official deploy guide:
  - `files` - object mapping file paths to SHA1 digests
  - `functions` - object mapping function names to SHA256 digests when functions are included
- Confirmed response fields from the guide:
  - `id` - deploy identifier
  - `required` - array of required file SHA1s to upload
  - `required_functions` - array of required function SHA256s to upload

### 5) Upload a deploy file
- Method: `PUT`
- Canonical path family confirmed from the guide example: `/api/v1/deploys/{deploy_id}/files/{file_path}`
- Concrete example shown in the docs: `PUT /api/v1/deploys/{deploy_id}/files/index.html`
- Purpose: upload file contents after the file-digest deploy creation step reports them as required.
- Important usage notes from the guide:
  - send file contents as the request body
  - use `Content-Type: application/octet-stream`
  - escape the `file_path` parameter
  - file paths must not include `#` or `?`

### 6) List account environment variables
- Method: `GET`
- Path: `/api/v1/accounts/{account_id}/env`
- Full URL: `https://api.netlify.com/api/v1/accounts/{account_id}/env`
- Purpose: list account-scoped environment variables.
- Path parameter:
  - `account_id` - account identifier
- This route family is listed in the official getting-started page's common-endpoints inventory and in the reviewed autogenerated route inventory for the same official docs host.

## Pagination
From the official getting-started page:
- responses over `100` items are paginated by default
- maximum page size is `100`
- query parameters:
  - `page`
  - `per_page`
- pagination URLs are exposed in the `Link` header with rel values such as:
  - `next`
  - `last`
  - `prev`

## Rate limits
From the official getting-started page:
- most requests: up to `500 requests per minute`
- deploys through the API: up to `3` times per minute and up to `100` times per day
- rate-limit headers shown by the docs:
  - `X-RateLimit-Limit`
  - `X-RateLimit-Remaining`
  - `X-RateLimit-Reset`

## Error / response notes
- The reviewed getting-started page focused on auth, pagination, deploy flow, and common endpoint patterns rather than publishing a single unified error schema.
- Route behavior is primarily conventional REST with JSON responses, except binary file uploads that use raw request bodies.

## Important usage notes
- Netlify's docs emphasize two deploy strategies: file-digest uploads and whole-ZIP uploads.
- The file-digest flow is multi-step: create site if needed, create deploy, upload only files/functions returned as required, then poll deploy state.
- The official page also links to a dedicated OpenAPI reference for exploring the wider route surface beyond the commonly used endpoints summarized here.

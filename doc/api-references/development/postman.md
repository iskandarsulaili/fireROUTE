## Authentication
From the current official learning docs:
- Auth type: API key.
- Every API request must send `X-API-Key: <your_postman_api_key>`.
- API keys inherit the caller's Postman permissions.
- The docs also note a separate concept of **collection access keys**, but those are for granting read-only access to a shared collection rather than for general Postman API management.

## Common request/response conventions
- Official learning docs consistently point users to the Postman API under `https://api.postman.com`.
- The reviewed pages describe the API as JSON-based.
- The official getting-started tutorial explicitly documents `401 Unauthorized` when a request is sent without valid authorization.
- The public docs state that rate limits are applied per user.

## Manually confirmed endpoint set

### 1) Get the authenticated user
- Method: `GET`
- Path: `/me`
- Full URL: `https://api.postman.com/me`
- Purpose: return information about the user who owns the API key used for the request.
- Auth: required via `X-API-Key`.
- Request parameters explicitly confirmed on the reviewed getting-started page:
  - none
- Response notes from the official tutorial:
  - unauthenticated request returns `401 Unauthorized`
  - authenticated request returns the API-key owner information in a successful JSON response

## Rate limits
From the official rate-limits page:
- Standard access limit: `300` requests per minute, per user.
- The reviewed page explicitly documents these response headers:
  - `RateLimit: limit=300, remaining=###, reset=##`
  - `RateLimit-Policy: 300;w=60`
  - `X-RateLimit-Limit` / `RateLimit-Limit`
  - `X-RateLimit-Remaining` / `RateLimit-Remaining`
  - `X-RateLimit-Reset` / `RateLimit-Reset`
  - `X-RateLimit-RetryAfter` / `RetryAfter`
  - `RateLimit-Limit-Month` / `X-RateLimit-Limit-Month`
  - `RateLimit-Remaining-Month` / `X-RateLimit-Remaining-Month`
- The docs also say monthly call limits depend on the Postman plan.

## Errors and response-format notes
- The official getting-started page explicitly demonstrates `401 Unauthorized` for a missing/invalid API key.
- The reviewed learning pages did not publish one single canonical global error-envelope schema in the accessible text pages.
- The rate-limits page documents retry-related headers when the rate limit is exceeded.

## Blocker note on route-level reference coverage
I tried both of Postman’s current official route-reference surfaces in this session:
- the `https://api.postman.com/` documentation host
- the linked Postman Public Workspace documentation viewer on `postman.com`

In this browser session, both official route-reference surfaces were unreliable:
- the `api.postman.com` host redirected into the public-workspace documentation experience rather than exposing a clean route catalog directly
- the workspace documentation UI repeatedly showed fetch failures like **“Something Went Wrong”** and **“There was an error while fetching the documentation for this item”**
- when drilling into collection folders/requests, the viewer also produced **“Folder not found”** states

Because of that, I only documented the single `/me` route that is explicitly described on the accessible official learning page, plus the auth and rate-limit behavior confirmed from the official learning docs.

## Important usage notes
- Postman’s currently reachable learning-doc pages are excellent for auth, quota, and onboarding details, but they are not a full substitute for the endpoint-by-endpoint reference when the workspace viewer is failing.
- The public docs strongly encourage users to fork the official Postman API collection in the Postman Public Workspace.
- The official route-reference host appears to be coupled to Postman’s web documentation viewer rather than a static standalone reference.

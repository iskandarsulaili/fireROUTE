- Public API base URL documented by provider: `https://www.onemap.gov.sg`
- Transport: HTTPS
- Auth model: bearer-style access token obtained from the Authentication API and then sent in the `Authorization` header on documented geocoding/location routes
- Response format: JSON

## Product and access notes
- The official introduction page describes OneMap as the authoritative national map of Singapore operated by the Singapore Land Authority (SLA).
- The docs currently display an important banner saying the Search API now requires token-based authentication.
- The Authentication page says tokens are valid for `3 days`, do not auto-renew, and must be regenerated by re-authenticating with the same credentials after expiry.
- The same page also says map services do not require the token, but the inspected geocoding/location routes on the docs pages all document an `Authorization` header requirement.

## Rate limits, pagination, and errors
- Numeric quota values are not published on the inspected pages.
- The docs consistently document `429 - API limit(s) exceeded` or `429 - API limit exceeded`, but not a concrete per-day or per-minute cap.
- There is no cursor-based pagination model documented. The only inspected paging control is `pageNum` on the Search route.
- The following error families are repeatedly documented across the inspected routes:
  - `400` for missing/invalid parameters or missing bearer token
  - `401` for expired or invalid tokens
  - `403` for forbidden role/component access
  - `429` for exceeded API limits

## 1) Authentication token generation
- Method: `POST`
- Path: `/api/auth/post/getToken`
- Full URL: `https://www.onemap.gov.sg/api/auth/post/getToken`
- Purpose: authenticate a registered OneMap user and return an access token plus expiry timestamp

Documented request body:
- `email` - required registered email address
- `password` - required OneMap password

Response notes:
- sample response fields shown: `access_token`, `expiry_timestamp`
- `expiry_timestamp` is shown as a Unix timestamp

Documented error notes:
- `401` authentication failed
- `404` user not registered or valid email/password not supplied

## 2) Search
- Method: `GET`
- Path: `/api/common/elastic/search`
- Full URL pattern: `https://www.onemap.gov.sg/api/common/elastic/search?searchVal={value}&returnGeom={Y|N}&getAddrDetails={Y|N}`
- Required header: `Authorization: {token}`
- Purpose: address / road / building / bus-stop / postal-code search for Singapore data

Documented query parameters:
- `searchVal` - required search text
- `returnGeom` - required `Y` or `N`
- `getAddrDetails` - required `Y` or `N`
- `pageNum` - optional page number

Response notes:
- sample response includes `found`, `totalNumPages`, `pageNum`, and `results`
- sample result fields include `SEARCHVAL`, `BLK_NO`, `ROAD_NAME`, `BUILDING`, `ADDRESS`, `POSTAL`, `X`, `Y`, `LATITUDE`, `LONGITUDE`, and `LONGTITUDE`

## 3) Reverse geocode (SVY21)
- Method: `GET`
- Path: `/api/public/revgeocodexy`
- Full URL pattern: `https://www.onemap.gov.sg/api/public/revgeocodexy?location={x},{y}&buffer={meters}&addressType={All|HDB}`
- Required header: `Authorization: {token}`
- Purpose: reverse geocode SVY21 coordinates to nearby address information

Documented query parameters:
- `location` - SVY21 `X,Y` coordinate pair
- `buffer` - optional `0-500` meters
- `addressType` - optional `HDB` or `All`

Response notes:
- sample response returns `GeocodeInfo` array entries with `BUILDINGNAME`, `BLOCK`, `ROAD`, `POSTALCODE`, `XCOORD`, `YCOORD`, `LATITUDE`, and `LONGITUDE`

## 4) Reverse geocode (WGS84)
- Method: `GET`
- Path: `/api/public/revgeocode`
- Full URL pattern: `https://www.onemap.gov.sg/api/public/revgeocode?location={lat},{lon}&buffer={meters}&addressType={All|HDB}`
- Required header: `Authorization: {token}`
- Purpose: reverse geocode WGS84 coordinates to nearby address information

Documented query parameters:
- `location` - WGS84 `latitude,longitude` pair
- `buffer` - optional `0-500` meters
- `addressType` - optional `HDB` or `All`

Important official notes:
- reverse geocode is available in both SVY21 and WGS84 forms
- the docs say the maximum buffer/radius is `500m` for buildings and `20m` for roads
- fields without value return as `NIL`
- unnamed buildings can return `null`
- by default the system returns up to `10` nearest buildings

## 11) Planning area polygons
- Method: `GET`
- Path: `/api/public/popapi/getAllPlanningarea`
- Full URL pattern: `https://www.onemap.gov.sg/api/public/popapi/getAllPlanningarea?year={year}`
- Required header: `Authorization: {token}`
- Purpose: return all URA planning-area polygons

Documented query parameters:
- `year` - optional; available values shown are `1998`, `2008`, `2014`, and `2019`; latest data is returned when omitted

Response notes:
- sample response returns `SearchResults` items with fields such as `pln_area_n` and `geojson`

## fireROUTE integration notes
- OneMap is a good candidate when fireROUTE needs Singapore-specific address search, reverse geocoding, planning-area overlays, or coordinate conversion.
- Token acquisition is an explicit first step; adapters should separate credential exchange from normal route calls and cache the token until the published three-day expiry.
- The docs expose multiple coordinate systems. fireROUTE should preserve CRS-specific route choice rather than assuming all reverse lookups use WGS84.

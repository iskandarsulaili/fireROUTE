## API overview
- Base URL: `https://dev.to/api`
- API version documented here: `v1`
- Authentication:
  - `accept: application/vnd.forem.api-v1+json` is required for v1 requests
  - `api-key: <user API key>` is required for authenticated operations
  - the official v1 docs say some endpoints are publicly accessible without authentication
- Response format: JSON
- Date/time format: RFC 3339 unless otherwise specified
- Rate limits: no numeric rate-limit table is published on the reviewed official API pages

## Versioning and auth notes
- The official Forem docs still expose both `version 0` and `version 1`
- The API landing page says all v0 endpoints are available in v1, that v0 is deprecated, and that clients should prefer v1
- API keys are generated by the user from their Forem settings page

## Confirmed request parameters and bodies
### `GET /articles`
- `page` — integer, default `1`
- `per_page` — integer, default `30`, min `1`, max `1000`
- `tag` — single tag filter
- `tags` — comma-separated tag filter
- `tags_exclude` — comma-separated exclusion filter
- `username` — user or organization filter
- `state` — `fresh`, `rising`, or `all`
- `top` — number of days for popularity window
- `collection_id` — collection filter

### `POST /articles`
- JSON body root: `article`
- Reviewed fields on the official page:
  - `title`
  - `body_markdown`
  - `published`
  - `series`
  - `main_image`
  - `canonical_url`
  - `description`
  - `tags`
  - `organization_id`

### `GET /comments`
- `a_id` — article identifier
- `p_id` — podcast episode identifier

### `POST /reactions` and `POST /reactions/toggle`
- `category` — one of `like`, `unicorn`, `exploding_head`, `raised_hands`, `fire`
- `reactable_id` — integer target identifier
- `reactable_type` — `Comment`, `Article`, or `User`

### `GET /readinglist`
- `page` — integer, default `1`
- `per_page` — integer, default `30`, min `1`, max `1000`

### `POST /admin/users`
- Officially documented body fields shown on the page: `email`, `name`

## Response, pagination, and errors
- The v1 docs return JSON examples for all reviewed operations
- Officially visible response-code coverage across the reviewed v1 spec includes:
  - `200` on successful reads and reaction writes
  - `201` on article creation
  - `204` on some delete/unpublish-style operations
  - `401` unauthorized
  - `404` not found
  - `422` validation / unprocessable entity
- Pagination is explicitly documented on list-style endpoints such as articles and reading list
- The reviewed article-list docs say pages default to `30` results

## Important usage notes
- `GET /articles` defaults to featured, published articles ordered by descending popularity
- `GET /comments` returns top-level comments with nested children as threads
- `GET /comments/{id}` returns the root comment plus descendants as a thread
- Reaction writes are side-effecting and require authentication
- The official docs mix public and authenticated surfaces under the same base URL, so fireROUTE should treat auth as route-specific rather than globally mandatory

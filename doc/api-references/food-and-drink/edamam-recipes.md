# Edamam recipes

Official pages manually reviewed:
- https://developer.edamam.com/edamam-docs-recipe-api
- https://developer.edamam.com/edamam-docs-recipe-content-management-api

## Overview
- Base URL documented on both reviewed official pages: `https://api.edamam.com`
- Public recipe search auth: `app_id` + `app_key`
- Private recipe management auth: HTTP Basic auth with `app-id` as username and `app-key` as password
- Response format: JSON
- Compression note from the reviewed docs: gzip is supported via `Accept-Encoding: gzip`
- Important plan note from the reviewed docs: not all response fields are available on all plans

Manual route count confirmed from the reviewed official docs: **15** recipe-related operations.

## Confirmed endpoints

### Public Recipe Search API
| Method | Path | Purpose |
|---|---|---|
| GET | `/api/recipes/v2` | Search for recipes |
| GET | `/api/recipes/v2/by-uri` | Look up one or more recipes by URI |
| GET | `/api/recipes/v2/{id}` | Look up one recipe by Edamam ID |
| POST | `/api/shopping-list/v2` | Build a shopping list from meal quantities |

### Private recipe book / management routes
| Method | Path | Purpose |
|---|---|---|
| POST | `/api/recipe-book/v1/{app-id}/draft` | Create draft with generated recipe ID |
| GET | `/api/recipe-book/v1/{app-id}/draft/{recipe-id}` | Get draft recipe |
| PUT | `/api/recipe-book/v1/{app-id}/draft/{recipe-id}` | Create or update draft recipe |
| DELETE | `/api/recipe-book/v1/{app-id}/draft/{recipe-id}` | Delete draft recipe |
| GET | `/api/recipe-book/v1/{app-id}/draft/{recipe-id}/search-view` | Get draft in search-view format |
| POST | `/api/recipe-book/v1/{app-id}/draft/{recipe-id}/publish` | Publish draft |
| GET | `/api/recipe-book/v1/{app-id}/published/{recipe-id}` | Get published recipe |
| DELETE | `/api/recipe-book/v1/{app-id}/published/{recipe-id}` | Delete published recipe |
| GET | `/api/recipe-book/v1/{app-id}/published/{recipe-id}/search-view` | Get published recipe search-view |
| GET | `/api/recipe-book/v1/{app-id}` | List user recipes |
| GET | `/api/recipe-book/v1/{app-id}/info/{recipe-id}` | Get recipe record information |

## Confirmed parameters and auth details

### Public search routes
The reviewed recipe-search docs confirm these auth/query conventions:
- `app_id`: required application ID
- `app_key`: required application key

Confirmed route behaviors from the reviewed docs:
- `GET /api/recipes/v2` is the main search endpoint
- `GET /api/recipes/v2/by-uri` resolves recipes from one or more recipe URIs
- `GET /api/recipes/v2/{id}` looks up a specific recipe by ID
- `POST /api/shopping-list/v2` accepts a request body describing meal quantities / plan items

Other public-search notes explicitly stated in the reviewed docs:
- `_links.self` URLs from recipe responses can be used to retrieve a recipe again later
- `Accept-Language` can be used to request translated recipe/search-view responses where supported
- Active-user-tracking plans may require a user ID header, and the docs say requests error if the feature is expected but the header is missing

### Private recipe management routes
The reviewed management docs confirm:
- path parameter `app-id` identifies the recipe-book account/application
- path parameter `recipe-id` identifies the recipe record
- auth is HTTP Basic, with `app-id` as username and `app-key` as password

Important management headers documented on the reviewed page:
- `Edamam-Record-Version`: used for optimistic locking and synchronization
- `Edamam-Record-State`: returned to indicate the record state
- `Content-Language`: language of recipe content being sent
- `Accept-Language`: desired language of recipe content/search-view being returned

The reviewed docs describe these recipe states:
- `draft`
- `published`
- `modified`
- `deleted`

## Request/response notes
- Public and private recipe APIs return JSON.
- The reviewed docs explicitly say Edamam's public recipe corpus contains web recipes and usually provides source URLs rather than copyrighted cooking instructions.
- Nutrition data is generated by Edamam.
- Shopping list requests aggregate ingredient quantities across recipe/meal plans.
- The management API distinguishes draft and published variants of the same recipe record.

## Rate limits and quota notes
- No numeric rate-limit values are published on the reviewed recipe search or recipe management pages.
- The docs do not provide a fixed public requests-per-minute figure on the reviewed pages.
- The reviewed docs do state that field availability and behavior depend on plan/agreement.

## Important usage notes
- The reviewed public docs describe the Recipe Search API and Recipe Management API as linked but separate accounts so search access can see published recipes without modifying them.
- Recipe translations are supported, but the reviewed management docs say the analyzer still requires an English variant in all cases.
- The public docs say gzip compression is supported and can materially reduce payload size.
- The management API uses optimistic locking; fireROUTE should preserve record-version headers where present.
- The public recipe docs note that Edamam also offers fully licensed recipes separately; the standard Recipe Search API is primarily a web-recipe index with Edamam-generated nutrition.

## fireROUTE notes
- Treat `GET /api/recipes/v2` as the primary search route.
- Keep `/api/recipes/v2/by-uri` and `/api/recipes/v2/{id}` as explicit lookup helpers.
- Keep public search auth (`app_id`, `app_key`) separate from private recipe-book Basic auth.
- Preserve `Accept-Language`, `Content-Language`, `Edamam-Record-Version`, and `Edamam-Record-State` header handling on private management routes.
- Treat shopping list creation as a separate POST workflow, not a search variant.

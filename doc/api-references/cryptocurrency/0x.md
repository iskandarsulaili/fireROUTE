## Current docs-state notes
- The repo's old README link `https://0x.org/api` is no longer the stable technical reference entrypoint in this environment; the current browsable first-party docs are on `docs.0x.org`.
- The reviewed API overview still describes four active surfaces: `Swap`, `Gasless`, `Sources`, and `Trade Analytics`.
- A banner on the docs site says `Cross-Chain API is in private beta`; it was not included in the confirmed public route count.

## Authentication and request model
The reviewed `API reference` overview requires these headers on all API calls:

```http
0x-api-key: YOUR_API_KEY
0x-version: v2
```

Confirmed request behavior from the reviewed official pages:
- All requests use HTTPS against `https://api.0x.org`
- Missing `0x-version` may be rate-limited or rejected
- `chainId` is a first-class request selector across the reviewed Swap, Gasless, and Sources pages
- Common quote parameters shown repeatedly in examples include `chainId`, `buyToken`, `sellToken`, `sellAmount`, and `taker`
- `Content-Type: application/json` is used on the reviewed `POST /gasless/submit` route

## Route-level notes from the reviewed docs
### Swap
- `GET /swap/allowance-holder/price` returns indicative swap pricing and shows `allowanceTarget`, `fees`, and `issues` fields in the example response.
- `GET /swap/allowance-holder/quote` returns an executable quote and the reviewed docs describe it as producing calldata / unsigned transaction data for execution.
- The current docs navigation still exposes both `Allowance Holder` and `Permit2` approval models for Swap.
- `GET /swap/chains` returns a `chains` array with `chainId` and `chainName` fields.

### Gasless
- `GET /gasless/price` and `GET /gasless/quote` mirror swap-style parameters but add gasless-specific fee / approval semantics.
- `POST /gasless/submit` accepts a JSON body with top-level `chainId` and a `trade` object; the reviewed example includes `type: "settler_metatransaction"` and nested EIP-712 payload details.
- `GET /gasless/status/:tradeHash` returns a route-specific status response; the reviewed example shows `status`, `transactions`, and `zid`.
- `GET /gasless/gasless-approval-tokens` returns a `tokens` array of supported token addresses.
- `GET /gasless/chains` returns a gasless-supported `chains` array.

### Sources
- `GET /sources` returns the list of supported liquidity sources for a given `chainId`.
- The reviewed example includes sources such as `0x_RFQ`, `Ambient`, `BalancerV2`, `Curve`, `Maverick`, `SushiSwap`, `UniswapV2`, and `UniswapV3`.

### Trade Analytics
- `GET /trade-analytics/swap` and `GET /trade-analytics/gasless` are the currently browsable historical-trade surfaces.
- Both reviewed analytics routes accept `cursor`, `startTimestamp`, and `endTimestamp` query parameters.
- The reviewed example responses return `nextCursor` plus a `trades` array with fields such as `appName`, `chainId`, `buyToken`, `sellToken`, `fees`, `gasUsed`, `protocolVersion`, and `timestamp`.

## Parameters, pagination, and errors
### Common parameters seen in the reviewed docs
- `chainId` — chain selector
- `buyToken` — token being bought
- `sellToken` — token being sold
- `sellAmount` — amount of the sell token
- `taker` — taker wallet address

### Analytics pagination
- Trade Analytics routes use `cursor` pagination
- The docs examples also show time-window filters `startTimestamp` and `endTimestamp`
- The reviewed analytics responses expose `nextCursor` for follow-up paging

### Error handling confirmed from the reviewed pages
- Many reviewed routes expose `400 Bad Request Error`
- Reviewed routes also commonly expose `500 Internal Server Error`
- `GET /gasless/status/:tradeHash` additionally exposes `404 Not Found Error`
- The reviewed docs pages are route-specific and do not publish one shared global error envelope on the pages inspected in this pass

## Rate limits
- I did not find a numeric public quota table on the route pages reviewed in this pass.
- The official overview explicitly warns that requests missing the required `0x-version` header may be rate-limited or rejected.

## Important usage notes
- 0x's current first-party reference has moved to `docs.0x.org`; do not rely on the old `0x.org/api` marketing URL as the canonical docs entrypoint.
- `Swap` and `Gasless` are separate operational surfaces and should remain separate in fireROUTE normalization.
- The reviewed docs still present both `Allowance Holder` and `Permit2` approval models for Swap.
- `Gasless` uses a multi-step quote -> submit -> status workflow rather than a single synchronous quote-only lifecycle.
- `Sources` and `Trade Analytics` are real route families in the current docs and should not be collapsed into marketing-only notes.
- The docs' Cross-Chain API beta banner indicates an additional private-beta surface, but it was excluded from the confirmed public route inventory because route-level public reference pages were not reviewed in this pass.

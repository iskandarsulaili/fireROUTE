## Shared request model
### Path parameters
- `source_id` - SHARE source identifier used on `/sources/{source_id}/`; the official collection response exposed values such as `DC0DE-ADB-EEF`

### Query parameters
- `page[cursor]` - cursor-pagination parameter exposed by the `next` link on `/sources/`

## Endpoint notes from official pages
### `GET /`
- Returns the root discovery document.
- The browsed JSON body exposed these top-level links:
  - `sources`
  - `users` -> `https://share.osf.io/api/v2/user/`
  - `status`
  - `rss`
  - `atom`
- The rendered API browser showed `Allow: GET, HEAD, OPTIONS`.

### `GET /status`
- Returns a JSON:API-style status record.
- The reviewed response body included:
  - `data.id = "1"`
  - `data.type = "Status"`
  - `attributes.status = "up"`
  - `attributes.version = "25.6.1"`
- The rendered API browser showed `Allow: GET, HEAD, OPTIONS`.

### `GET, POST /sources/`
- Returns the source collection.
- The reviewed response exposed cursor pagination through `links.next` and showed a concrete next-page URL using `page[cursor]`.
- Each source item in the reviewed page included:
  - `type = "Source"`
  - a numeric `id`
  - attributes such as `name`, `homePage`, and `longTitle`
  - a `sourceConfigs` relationship with `meta.count`
  - a `links.self` URL pointing to `/sources/{source_id}/`
- The rendered API browser showed `Allow: GET, POST, HEAD, OPTIONS`.

### `GET, PUT, PATCH, DELETE /sources/{source_id}/`
- The reviewed example detail route `GET /sources/DC0DE-ADB-EEF/` returned a single `Source` object.
- The official HTML API browser advertised mutating methods with `Allow: GET, PUT, PATCH, DELETE, HEAD, OPTIONS`.
- The reviewed detail response repeated the collection fields and relationship data for `sourceConfigs`.

### `GET /user/`
- The reviewed unauthenticated request returned `HTTP 200 OK` with `{"data": []}`.
- The rendered API browser showed `Allow: GET, HEAD, OPTIONS`.
- The reviewed page did not expose any additional auth instructions or write methods.

### Feed endpoints
- The root discovery document exposes two feed routes:
  - `GET /feeds/rss`
  - `GET /feeds/atom`
- The reviewed root page did not document additional feed query parameters.

## Pagination and format notes
- The reviewed API browser consistently reported `Content-Type: application/vnd.api+json` for the JSON API routes.
- `/sources/` uses cursor pagination rather than simple numbered pages in the browsed response.
- Collection responses include a top-level `links` object and a top-level `data` array.
- Detail/status responses include a top-level `data` object.

## Error notes
The invalid-ID check against `https://share.osf.io/api/v2/sources/NOT-A-REAL-ID/` returned `HTTP 400 Bad Request` with this JSON:API-style error structure:

```json
{
  "errors": [
    {
      "detail": "Invalid ID",
      "status": "400",
      "source": {
        "pointer": "/data"
      },
      "code": "invalid"
    }
  ]
}
```

## Important usage notes
- The in-product `Documentation` link rendered an autogenerated Read the Docs placeholder during review, so the live API browser pages themselves were the reliable official source in this pass.
- The root document is the key discovery surface because it exposes the other published route families directly.
- The reviewed public pages confirm readable GET access without authentication, but they do not explain how the advertised write methods on source resources are authorized.
- The browsed endpoint pages consistently surfaced `OPTIONS` in their `Allow` headers, indicating that the service publishes method metadata per route even when the browser view defaults to `GET`.

## fireROUTE normalization notes
- Use `https://share.osf.io/api/v2` as the canonical base URL.
- Model SHARE as a small JSON:API discovery/document service with one cursor-paginated collection (`/sources/`), one detail route, one status route, one user route, and two feed endpoints.
- Preserve the native `page[cursor]` parameter name exactly as published.
- Treat write support on `/sources/` and `/sources/{source_id}/` as officially advertised but auth-unclear until a future manual pass finds first-party authorization guidance.
